## 3. 本次修复（3 处，均为"整理副作用"）

### 3.1 `tools/04_01_gate_runner.py` 路径失效 ✅ 已修
整理后主脚本从 `04_pySCENIC/` 移到了 `section3_HAVCR2-MAFB调控模块/code/04_pySCENIC/`，
runner 里写死的 `MAIN` 路径找不到文件。已改为 **新位置优先 → 旧位置回退 → 全局兜底搜索**。

### 3.2 归档 `GSE182434/scenic/` 缺 33 个 png ✅ 已补（15.7 MB）
`04_01_pyscenic_downstream_stats_figures.py` 的 `need_redraw()` 用
`OUT_DIR/{name}.png` 是否存在来判断"该节是否跳过"。整理时把 png 全清了，导致
所有 gate 都判为"需重画"，于是执行到脚本内一个**历史坏块**（第 214 行用 `ax_heat`，
而它直到 1454 行才定义）→ `NameError`。
脚本自带注释明确写着"靠图已存在就跳过绕开这段代码"。
**补回 png 即恢复原判定逻辑。**

### 3.3 归档 `celloracle0331/` 缺 94 个文件 ✅ 已补（30.2 MB）
缺的正是 `figures/` 下 **Fig4 全部面板的 svg/png 源**（`05_90_reproduce_figures_local.py`
的 `OUT_DIR`）。原产物已在 `00_共用/历史版本/fig4原产物_20260913/` 留档。

> **共性教训**：整理时"排除图件"的规则过于激进。数据目录下的 png/svg
> 未必是"纯输出图"——有些是**缓存标记**或**面板源**，删了就破坏复现。
> ⇒ 后续清理数据目录时，需逐目录确认是否存在"以产物存在性做判断"的脚本。

## 6. 复现操作指南

```bash
# 0) 数据根：默认自动解析到 00_共用/数据/，无需设置
cd <仓库>/DLBCL_HMGB1_HAVCR2_MAFB

# 1) 全流程分析（按 section）
python run_all.py --check          # 输入预检
python run_all.py --list           # 列出各节脚本
python run_all.py --stage 4        # 只跑 section4
python run_all.py                  # 全部

# 2) 一键重建主图
python tools/rebuild_fig1.py --fast
python tools/rebuild_fig3.py
python tools/fig_compose_pdf.py results/assembled/figN.json   # N=2,4,5,6,7

# 3) 单面板重渲（缩画布保字号）
python tools/run_with_retrofit.py <脚本.py> <显示宽in> <字号pt> --out <输出目录>
```

> 指定 Python：`run_all.py` 用 PATH 中的 `python`，请确保是**系统 Python310**。
> 或：`export PATH="/c/Users/admin/AppData/Local/Programs/Python/Python310:$PATH"`
